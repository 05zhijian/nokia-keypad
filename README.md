# 仿真按键机

把一张老式按键手机的照片，做成一个**真的能用**的 App：按键按得下去、有真实的拨号音和震动、屏幕是活的单色 LCD。

Flutter / Android。屏幕全屏、常亮，打开之后这台手机就"变成"那台按键机。

## 做了什么

| 功能 | 说明 |
|---|---|
| 待机 / 主菜单 | 层级导航，右软键逐级返回 |
| 短信 | 通知提示 → 阅读；**T9 多按输入**能真的打字并发送 |
| 通讯录 | 读取系统通讯录（只读），列出真实联系人 |
| 假来电 | 从通讯录选人，以他的名义来电，铃音循环 |
| 模拟拨号 | 待机按绿键 → 拨号盘 → 呼叫中（放铃回音）→ 接通计时 |
| 铃声编辑器 | 复刻 Nokia Composer：`1`-`7` 是音阶，`8`/`9` 改时值，`*` 换八度，`#` 升半音，`0` 休止 |
| 手感 | 按键音、震动、按压下沉三者同步 |

## 几个值得说的技术点

### 按键音是 DTMF 双音，不是「嘀」一声

老式电话的拨号音是**两个正弦波叠加**（行频 + 列频，ITU-T Q.23 标准）。
随手放一个单频 beep 会立刻出戏，所以频率表是查标准来的，每个键的音高都不同。

波形两端加了淡入淡出包络——直接切断正弦会在波形上留一个阶跃，听起来是「啪」的一声，
这是仿真按键音最容易露馅的地方。

### 按键瞬间不做任何计算

音频在启动时**一次性合成好、常驻内存**，按下时只剩一次播放调用。
如果每次按键都现算双音，延迟就压不住，手感立刻垮掉。

铃声编辑器的音符按「音高 + 时长」缓存，播放整段旋律前先预热，避免播到一半卡一下。

### 界面状态机

用一个**栈**建模诺基亚的层级导航：入栈 = 进入下一层，右软键出栈 = 返回。
栈空时是待机层，此时右软键不再是返回——这是真机的行为。

开机那屏（短信通知）是**压在待机之上**的一层，而不是待机本身。
这两者的区别在「按返回能不能退回待机」上是决定性的。

### 像素字体的字号必须吸附

中文像素字体只在**原生尺寸的整数倍**上栅格化才是锐利的。
给一个 47.3 这样的字号，字形会在像素格之间插值，糊成一片。
所以所有字号都经过一个吸附函数。

### 折行有两套，不能混用

- 自然语言用按「字宽」估算的折行（中文占 1 个字宽，ASCII 占半个），断行时优先在空格处断
- **铃声编辑器的记号序列必须整体换行**——`87` 被拆成 `8` 和 `7` 落在两行，
  读起来就是两个音符，意思全变了

### 长屏适配：多出来的高度要分两份

设计画布是照参考图量的固定比例。真机屏幕更长时，多出来的高度**一半给屏幕、一半给键盘**：

- 全给键盘 → 键盘越长越高，屏幕显得越来越小，比例就偏了
- 键盘内部再按权重摊进「上下留白 + 行间缝隙」，**键帽尺寸始终不变**

## 测试

**180 个**，覆盖：

- 音频合成（WAV 头、DTMF 频率表、包络、时长换算）
- 界面状态机（导航层级、软键语义、T9、拨号流程、来电）
- 折行（自然语言 / 记号序列）
- 键盘几何（导航键居中、与相邻键的间距）
- 版式快照（整机、长屏、各功能屏）

音频和状态机这两层是纯逻辑，不依赖真机和声卡，所以能完整测。
**唯独「读系统通讯录」那部分依赖权限与平台通道，测不到**——状态机那一侧用假的
数据源覆盖了，真机实现只有插上手机才知道。

## 构建

```bash
flutter pub get
flutter build apk --release --split-per-abi
```

要求 Flutter 3.32+ / Dart 3.8+。`minSdk` 是 24（通讯录插件的要求）。

```bash
flutter test                        # 跑全部测试
flutter test --update-goldens       # 版式有改动时重新生成快照
```
